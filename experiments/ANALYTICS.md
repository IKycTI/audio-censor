# Аналитика текста для экспериментов

Текст: [`text.md`](text.md), статья SearchInform «(Не) безопасный дайджест Halloween Edition:
взломанная Дания, ИИ-хакер и кофеварка-инсайдер» (Хабр, 31.10.2026), заголовок и 10 разделов.
Словарь: [`banned_words.json`](banned_words.json).

Всё ниже посчитано по **написанному** тексту, как если бы распознавание было идеальным. Это
эталон, с которым сравниваются результаты запусков: разница между эталоном и отчётом программы
даёт ошибки распознавания. Подсчёт повторяет правила программы (`src/decision/rules.rs`):
нижний регистр, только буквы и цифры, точное совпадение, нечёткое сравнение только если и слово,
и запись словаря не короче 4 символов. Дефис при чтении вслух разделяет слова
(«хакеры-антикапиталисты» — два слова).

## Текст

| Показатель | Значение |
|---|---|
| Слов (токенов) | 1205 |
| Различных слов | 717 |
| Символов без пробелов | 7928 |
| Чисел, записанных цифрами | 43 |
| Слов латиницей (названия компаний и т. п.) | 48 |
| Время чтения вслух | ≈ 8–10 мин (при 120–150 слов/мин) |

Числа при чтении произносятся словами («9 миллионов» — «девять миллионов»), поэтому
распознанных слов будет больше 1205. Латинские названия (ShinyHunters, Danfoss, Burger King)
Vosk запишет русскими словами из своего словаря или пропустит: на запрещённые слова это не
влияет, но `words_recognized` с числом слов текста напрямую не сравнить.

21 запуск × ~10 мин чтения ≈ 3,5 ч только на проигрывание (плюс 20 с загрузки модели и `delay_ms`
на каждый запуск). Если это слишком долго, можно взять часть разделов: запрещённые слова
распределены по всему тексту.

## Как сравнивать с отчётом

Подсчёт по журналу: `python3 experiments/score.py experiments/results/<серия>/<сеанс>.log`.

**Правило подсчёта — строгое.** Верным срабатыванием (TP) считается только словоформа из
эталона выше. Если Vosk распознал другую форму запрещённого слова, которой в тексте на этом
месте нет (в тексте «хакеров», распознано «хакера»; в тексте «взломали», распознано «взломал»),
это ложное срабатывание (FP): программа заглушила не то слово, которое было произнесено.
Правило одинаково для всех серий.

- `words_censored` — число новых интервалов, то есть заглушённых слов. В идеале равно
  TP + FP из таблицы для θ этого запуска.
- Для Precision и Recall по отдельности одного счётчика мало: нужно знать, какие именно слова
  заглушены. Сами заглушённые слова журнал не пишет, но на уровне `debug` (он включён во всех
  конфигурациях экспериментов) пишет все распознанные слова: строки «Получено N слов: [...]».
  Прогнав эти слова через правила словаря, можно восстановить TP и FP запуска.
- Разница с эталоном при θ = 1 (61 слово) показывает ошибки распознавания: слово не распознано,
  распознано другим словом или отброшено по `min_confidence` (серия E).
- Длинные слова («злоумышленник», «мошенничество») — первые кандидаты в опоздавшие интервалы
  при малой задержке (серия B).
