# Эксперименты для главы 4

Конфигурации для экспериментального исследования: каждая серия меняет **один** параметр
относительно базовой конфигурации, остальные параметры одинаковы. Так влияние параметра можно
отделить от остальных.

## Состав

```
experiments/
├── make_configs.py      # генератор конфигураций (база и серии заданы в начале файла)
├── text.md              # текст для чтения (статья с Хабра)
├── ANALYTICS.md         # аналитика текста и эталон: сколько слов должно быть заглушено
├── banned_words.json    # словарь для экспериментов (10 записей под text.md)
├── configs/             # сгенерированные конфигурации, по одной на запуск
└── results/<серия>/     # журналы и отчёты сеансов (создаётся при первом запуске)
```

Базовая конфигурация совпадает с `config/default.toml`, кроме устройств и частоты: взяты
`PipeWire Sound Server` и 44 100 Гц, как в проверенном сеансе. Если на другой машине нужны
другие устройства, поменяйте `BASE` в `make_configs.py` и перегенерируйте:

```sh
python3 experiments/make_configs.py
```

## Серии

| Серия | Параметр | Значения | Что смотреть |
|---|---|---|---|
| A_chunk | `chunk_size_ms` | 50, 100, 200, 400, 800 | загрузка CPU, задержка распознавания, точность |
| B_delay | `delay_ms` | 500, 1000, 1500, 2000, 3000, 5000 | опоздавшие интервалы (`late_intervals`) |
| C_partial | `partial_results` | on, off | задержка распознавания, `partial_intervals`, ложные срабатывания (`unconfirmed_partial_intervals`) |
| D_theta | `max_distance` | 0, 1, 2, 3 | Precision и Recall (по разметке текста) |
| E_conf | `min_confidence` | 0.0, 0.5, 0.7, 0.9 | Precision и Recall (по разметке текста) |

Базовые значения: `delay_ms = 5000`, `chunk_size_ms = 100`, `partial_results = true`,
`max_distance = 1`, `min_confidence = 0.0`. Внутри каждой серии базовая конфигурация повторяется
отдельным файлом (`A_chunk_0100`, `B_delay_5000`, `C_partial_on`, `D_theta_1`, `E_conf_000`),
чтобы у каждой серии были свои результаты в одинаковых условиях.

Всего 21 запуск.

## Подготовка

1. **Текст.** Выбрать текст и составить разметку: какие слова в нём считаются запрещёнными
   и сколько раз каждое встречается. Эти слова записать в `banned_words.json` (поле `words`,
   в нормальной форме). Разметка нужна для Precision и Recall: программа считает заглушённые
   слова, но не знает, сколько запрещённых слов было произнесено на самом деле.
   Стоит включить в текст:
   - короткие и длинные запрещённые слова (длинное слово проверяет условие задержки);
   - словоформы запрещённых слов (проверяют нечёткое сравнение);
   - допустимые слова, близкие к запрещённым на одну-две буквы (проверяют ложные срабатывания).
2. **Одна запись на все запуски.** Если читать текст вживую для каждого запуска, результаты
   будут различаться из-за самого чтения (темп, паузы, дикция), а не из-за параметров.
   Лучше записать текст один раз и проигрывать эту запись во всех 21 запуске.

### Подача записи на вход (Linux, PipeWire) — проверить перед серией

```sh
# виртуальное устройство, «монитор» которого станет микрофоном для демона
pactl load-module module-null-sink sink_name=exp_src sink_properties=device.description=exp_src
pactl set-default-source exp_src.monitor

# запись текста с реального микрофона (один раз)
pw-record --target <имя реального микрофона> experiments/text.wav

# проигрывание записи в виртуальное устройство (в каждом запуске)
pw-play --target exp_src experiments/text.wav
```

Демон с `input_device = "PipeWire Sound Server"` берёт источник по умолчанию, то есть
`exp_src.monitor`. После серии вернуть источник по умолчанию и выгрузить модуль
(`pactl unload-module module-null-sink`).

## Один запуск

```sh
cargo build --release
target/release/audio-censor -c experiments/configs/B_delay_1000.toml
```

1. Дождаться строки «audio-censor успешно запущен» (модель грузится около 20 с).
2. Запустить проигрывание записи.
3. После окончания записи подождать ещё `delay_ms` + 1 с, чтобы хвост прошёл буфер задержки.
4. Остановить демон: Ctrl+C или `audio-censor -c <тот же конфиг> shutdown`.

Отчёт появится в `experiments/results/<серия>/`: `<сеанс>.metrics.json` и строка в
`sessions.jsonl`. В отчёт записываются значения параметров, поэтому запуски внутри серии
различаются по ним, а не по имени файла.

### Загрузка CPU (серия A)

Программа загрузку процессора не измеряет, её нужно снять снаружи, например во время
проигрывания записи:

```sh
pidstat -u -p $(pgrep -x audio-censor) 1 > experiments/results/A_chunk/cpu_<чанк>.txt
```

(`pidstat` из пакета `sysstat`.)

## Что берётся из отчёта

| Поле | Для чего |
|---|---|
| `words_censored` | вместе с разметкой — Precision и Recall |
| `late_intervals` | хватает ли задержки (условие (15) главы 2) |
| `recognition_latency_avg_ms`, `recognition_latency_max_ms` | задержка распознавания (формула (12)) |
| `partial_intervals`, `unconfirmed_partial_intervals` | вклад промежуточных гипотез и их ложные срабатывания |
| `dropped_*`, `underrun_samples`, `drift_*` | не было ли сбоев звука во время запуска |
| `censored_words` | по каждой записи словаря: сколько раз сработала (`count`) и какими распознанными словами (`recognized_as`), по окончательным результатам. Сразу видно ложные срабатывания вроде «хантер» → «хакер»; при θ запуска даёт те же TP и FP, что `score.py` |
| `chunk_processing_avg_us`, `chunk_processing_max_us`, `chunks_processed` | время обработки одного чанка (Vosk + принятие решения), мкс — $τ_{proc}$ из условия (11): должно быть меньше `chunk_size_ms` × 1000. Отношение среднего к длительности чанка — коэффициент реального времени |
